# 監造工地筆記（site-log）

工地現場記錄與經驗庫。純前端 PWA，用 iOS Safari 開啟後「加到主畫面」就是一個 App。

## 兩種用法

- **專案導向** — 同一個案場底下，按日期記錄照片、錄音、逐字稿，收工前產出當日的
  公共工程監造日報表（五段式）草稿。
- **類型導向** — 同一件事在不同案場怎麼做，收在同一個分類底下，之後要設計時直接比對。
  內建 14 項一級分類（不能刪），底下可以自己加分類與子項。
  也可以直接在分類裡建一筆記錄而**不掛任何專案**——在別的工地看到的做法就適合這樣記，
  它會進經驗庫，但不會被算進任何一天的監造日報。之後想掛到某個案子，在記錄頁改就好。

## 資料放在哪裡

| 東西 | 位置 | 會不會上傳 |
|---|---|---|
| 照片 | 這台裝置的 IndexedDB | **永不上傳**（除非你在設定裡開啟，再逐張手動點送） |
| 錄音檔 | 這台裝置的 IndexedDB | 只有你按「送 Gemini 轉逐字稿」那一段才會 |
| 逐字稿、欄位 | 這台裝置的 IndexedDB | 你按「AI 整理」時會，而且送出前一定先給你看全文 |
| Gemini API key | 這台裝置的 IndexedDB | 不會，也不在備份 zip 裡 |

沒有後端、沒有帳號、沒有雲端同步。備份要自己按「匯出備份」，
用 iOS 分享選單存到「檔案」或雲端硬碟。

### 送出前一定會做的事

1. **代號替換** — 依你的對照表把真實案名、廠商換成代號。對照表本身永不上傳。
2. **敏感詞掃描** — 替換後還命中的字會標紅提醒。
3. **全文預覽** — 實際要離開這台裝置的文字直接顯示出來，可以當場改，也可以取消。

### AI 的界線

Gemini 在這裡只做「整理你說過的話」：修錯字、整理通順、抽出樓層／軸線／分類、
把內容分派到日報的五個欄位。它被明確禁止補充任何你沒說的工程見解或引用規範條號。

所有 AI 產出預設標示為 **未查證**（灰底虛線框）。你問過前輩或查過規範，
勾「已確認」之後才會變成正式狀態，經驗庫可以切換成只看已確認的內容。

## 免費層 vs 付費層

Gemini API 免費層的內容 Google 可能用於改善產品、也可能被人工審閱；付費層不會。
頂端永遠顯示你現在用的是哪一層。

**正式工作內容請用付費層，並先確認公司對第三方 AI 服務的規定。**

## 本機開發

```bash
node tools/dev-server.mjs 5199
```

零相依，不需要 `npm install`。改完直接重新整理。

重新產生 App 圖示：

```bash
node tools/make-icons.mjs
```

## 檔案結構

```
index.html            App 外殼
sw.js                 service worker（離線用）
css/style.css
js/app.js             hash router
js/db.js              IndexedDB 資料層
js/taxonomy.js        14 項固定分類
js/glossary.js        工地術語對照（本機錯字修正 + 餵給 AI 的提示）
js/gemini.js          Gemini 客戶端與所有 prompt
js/redact.js          代號替換與敏感詞掃描
js/confirm-upload.js  送出前預覽
js/media.js           相機、錄音、GPS
js/watermark.js       浮水印（只在顯示與匯出時疊，不燒原圖）
js/zip.js             自寫的 ZIP 產生器（零相依）
js/export.js          備份匯出
js/report-template.js 日報格式（要換成公司制式表格改這裡就好）
js/views/             各頁面
```

## 日報格式要換的時候

目前用的是公共工程監造日報表的通用格式
（臺北市政府工程施工及驗收基準 附表6，各機關版本大同小異）。
拿到公司的制式表格之後，只要改 `js/report-template.js` 和
`js/gemini.js` 裡的 `REPORT_SECTIONS`，其他地方不用動。
